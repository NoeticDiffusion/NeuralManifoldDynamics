## Infrastructure fix: generic `events_tsv` source type

### Problem
`task_state_label` — the column that drives `block_native` segment extraction — was
generated by hardcoded ds003838-specific code in `eeg.py`. No other dataset could produce
block_native windows without a custom code addition.

### Solution
Added a new `events_tsv` source type to `mndm/src/mndm/pipeline/state_labels.py`:

- Reads the BIDS `_events.tsv` for the current subject/task automatically (auto-resolves
  path from `dataset_root / sub-{id} / eeg / sub-{id}_task-{task}_events.tsv`).
- Labels each epoch window by last-value-carried-forward (LVCF) from the `trial_type`
  column in the events file.
- Supports `label_set` whitelist (only propagate selected trial_type values) and
  `reset_on_labels` (clear the LVCF label on specific events like `Boundary` or `Baseline`).
- Passes `task` and `raw_task` through `_evaluate_rule` so the BIDS path can be resolved.

Any future dataset only needs to add to its config:
```yaml
within_run_labels:
  datasets:
    my_dataset:
      enabled: true
      output_name: task_state_label
      write_to_stage: true
      write_to_labels: true
      codebook:
        MyEventLabel: 1
        AnotherLabel: 2
      rules:
        - id: my_dataset_task_state_from_events_tsv
          source:
            type: events_tsv
            trial_type_column: trial_type
            onset_column: onset
            label_set: [MyEventLabel, AnotherLabel]
            reset_on_labels: [Boundary]
```

## Design notes / limitations

1. **Short retention blocks** — each `Retention_*` block is ~6 s, yielding only 2 windows
   per trial (4 s window, 2 s step). For robust Jacobian / coupling estimation, consider
   aggregating same-condition trials into pseudo-blocks in a future analysis step.

2. **Retrieval phase dominates** — `Digits_Retrieval` (~18 s/trial × 400 trials = 39,306
   windows) will dominate any cohort-level analysis. May want to subsample or weight by
   condition when fitting MNPS projectors.

3. **Rest data missing for 8 subjects** — sub-002/003/004/005/006/008/009/011 lack rest
   recordings. Any rest vs. task comparison is N≤22.

4. **Event-locked: 0 events aligned** — the `event_locked` section used
   `source_label: derived:task_state_label` which currently maps to the derived labels
   (e.g., "Retention_Fast"). Since `event_types` in the config listed these same labels,
   it should have aligned — but produced 0 event rows (800 control rows for verbalwm).
   Needs investigation; possibly the source_label derivation timing mismatch.
