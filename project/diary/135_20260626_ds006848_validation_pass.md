## Actions taken

### LVCF fix (ecg.py)
`_build_task_label_intervals` now prefers `onset + duration` when duration > 0,
falling back to LVCF (next-event onset) when duration is 0 or absent. For
ds006848, all events have `duration=0.0` so LVCF is the active path — but
future datasets with meaningful durations benefit automatically.

Note: `Encoding_DigitValue_X` items in ds006848 have LVCF-expanded intervals of
~0.4–0.8 s (the actual ISI between digits in the encoding sequence). This is
correct for the HRV contamination use case: these are very short and the
dominant label in a 60-second HRV window will be determined by the longer-duration
labels (`Retention_*`, `Digits_Retrieval`).

### Confirmed current ds006848 HR problem
Pre-correction values in features.parquet:
- Group median HR: 98.6 bpm (healthy subjects should be ~70 bpm at rest)
- Group median RMSSD: 178.5 ms (extremely high — T-wave double detection signature)
- sub-021: HR 142–144 bpm, RMSSD 205–220 ms
- sub-022: HR 126–132 bpm, RMSSD 274–301 ms

These values are consistent with T-wave double detection (T-waves counted as
extra R-peaks → halved RR intervals → doubled HR).
