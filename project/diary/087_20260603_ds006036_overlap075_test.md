# ds006036 overlap 0.75 photic test

## Research question

Can `overlap_frac_ge: 0.75` recover a useful amount of photic-labeled data
relative to `fully_contained`, while still staying cleaner than the historical
midpoint-based block surface?

## Config change

Updated `mndm/config/config_ingest_ds006036.yaml`:

```yaml
stage_blocking:
  window_membership:
    mode: "overlap_frac_ge"
    min_overlap_fraction: 0.75
```

This policy requires at least 75% of each 8 s MNPS window to overlap the
inferred photic block before the photic stage is assigned.

current compromise among the tested policies.
