# ds004574 metadata overlay

Date: 2026-06-02

## Question

Set up an EEG ingest overlay for `ds004574` with emphasis on getting the cohort
metadata mapping right, and inspect how the root event metadata should be handled.

## Dataset notes

`ds004574` is a BIDS EEG oddball cohort with:

- `146` subjects
- `98` Parkinson participants
- `48` controls
- one BIDS task: `Oddball`
- one EEG recording per subject in EEGLAB `.set/.fdt` format

Relevant metadata sources:

- `participants.tsv`
- `participants.json`
- `task-Oddball_events.json`
- per-subject `*_events.tsv`
- per-subject `beh/*.tsv`

## Key metadata finding

The important cohort metadata are already in `participants.tsv`:

- `GROUP` (`PD` or `Control`)
- `AGE`
- `GENDER`
- `MOCA`
- `UPDRS`
- `TYPE` (`1` = PD, `0` = Control)

The root `task-Oddball_events.json` documents the generic event roles:

- `S  1` = precue
- `S  2` = arrow cue
- `S  3` = response

However, the richer trial subtype information described in the README
(`standard`, `oddball auditory`, `oddball visual`) is **not** carried in the BIDS
`*_events.tsv` files. That richer metadata lives in per-subject behavior tables,
for example:

- `sub-001/beh/sub-001_task-Oddball_beh.tsv`

with columns such as:

- `Odd: Visual`
- `Odd: Audio`
- `CueDirection`
- `Acc`

## Decision

Use a conservative config-only overlay now:

- map cohort-level metadata from `participants.tsv`
- normalize `GROUP` to:
  - `PD -> Parkinson`
  - `Control -> Control`
- use `task` from filename:
  - `Oddball -> oddball`
- set run-level `condition` to:
  - `not_applicable`

Do **not** promote `S  1 / S  2 / S  3` to the canonical stage axis yet.

Reason:

- these are point events inside long overlapping 8-second windows
- a single per-window stage label would be misleading
- the actual oddball subtype of interest is only available in `beh.tsv`, not in
  the BIDS event stream

## Evidence category

- Internal validated result:
  - `ds004574` can be ingested with a config-only overlay
  - cohort metadata mapping is working as intended for both PD and control cases
  - the BIDS event stream is too generic for trial-subtype staging without an
    additional behavior-table join
