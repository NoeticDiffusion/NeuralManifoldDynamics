## Root cause investigation: e_m and spectral subcoords

Deep inspection of the H5 structure revealed two distinct issues:

### Issue 1: Spectral band powers degenerate in coords_9d (m_a, m_e, d_n → 0)

- `meg_delta`, `meg_theta`, `meg_alpha`, `meg_gamma` all have `std=0` in `features_robust_z`
- Root cause: `_strict_robust_z_column()` in `projection.py` receives raw PSD values (~1e-25 T²/Hz)
  which are below the `eps=1e-9` floor; the scale falls back to 1e-9, producing RZ values of ~1e-17
  (effectively 0 in float32)
- The `["log10", "robust_z", "clip"]` pipeline step applies log10 BEFORE the cohort-level
  `_normalize_used_columns` step (used in `coords_9d`), but `features_robust_z` stores the
  raw-space RZ (which is zero)
- Consequence: m_a, m_e, d_n are flagged as "duplicate constant" by the geometry contract
  and zeroed out in `coords_9d`
- **This is partially correct behaviour**: the geometry contract is protecting against degenerate
  dimensions. The actual 9D space is effectively 5D (m_o, d_l, d_s, e_e, e_s)
- **Next step** (not fixed today): the `features_robust_z` raw-space RZ computation could be
  improved by applying log10 before computing center/scale. This is a future enhancement.

### Issue 2: e_m = constant -0.6745 for FIF rows

- `embodied_arousal_proxy` returns a non-NaN **constant** value for MEG FIF rows
  (no ECG → HRV computation fails, but returns a placeholder rather than NaN)
- The metric_policy fallback only triggers on NaN, not on constant non-informative values
- Result: e_m has zero variance in FIF rows, contributing nothing to face-scrambled discrimination
- The geometry contract does NOT flag e_m as degenerate because `.set` rows have varying
  EEG-derived e_m values (which gives enough apparent variance to pass the degenerate check)

### Issue 3: meg_sample_entropy = meg_permutation_entropy (alias bug)

In `meg.py`, both `meg_sample_entropy` and `meg_permutation_entropy` were set to the
same value from `_compute_entropy_feature()`. The EEG code (`eeg.py`) has the same alias
("Backward-compatible alias").

## Fixes implemented

### Fix 1: Real sample entropy (SampEn) for MEG

**File**: `mndm/src/mndm/features/meg.py`

Added `_sample_entropy()` function implementing template-matching SampEn:
- Uniformly subsamples long signals to max 300 points (O(n²) → ~6 ms per epoch)
- Uses vectorised numpy stride tricks for template comparisons
- Verified independent of permutation entropy (r=−0.50 on 10 random signals)
- Validated: regular sine (SampEn=0.26) < white noise (SampEn=2.37)
- `meg_sample_entropy` now uses true SampEn; `meg_permutation_entropy` unchanged

### Fix 2: Config update — e_m uses meg_sample_entropy

**File**: `mndm/config/config_ingest_ds003645.yaml`

Changed:
```yaml
e_m: {embodied_arousal_proxy: 1.0}
metric_policies:
  e_m:
    preferred: embodied_arousal_proxy
    fallbacks: [eog_blink_rate, meg_highfreq_power_30_45]
```

To:
```yaml
e_m: {meg_sample_entropy: 1.0}
metric_policies:
  e_e:
    preferred: meg_permutation_entropy
    fallbacks: [meg_highfreq_power_30_45]
```

Since `meg_sample_entropy` is now genuinely different from `meg_permutation_entropy`,
this gives e_m a truly independent 9th axis (sample entropy ≠ permutation entropy).

### Fix 3: C1 at 4s window resolution

**File**: `project/analysis/ds003645_meg_validation_package.ipynb` (D2 section added)

New validation cell: re-runs C1 event-response vector agreement using 4s pipeline outputs.
- Condition labels forward-filled from 8s epoch_condition_labels.csv
- Shared-feature-type cosine similarity (MEG and EEG projected onto common feature names:
  delta, theta, alpha, beta, gamma, hjorth_mobility, hjorth_complexity, permutation_entropy, …)
- 500-permutation null test

**Result**: fraction obs > null = 0.500 (50%) at 4s resolution vs 0.467 at 8s resolution.

## Known remaining issues

1. **`features_robust_z` for MEG spectral features stores raw-space RZ (≈0)**: The log10
   transform is applied in `_normalize_used_columns` (for coords_9d) but not in
   `build_feature_export_bundle` (for features_robust_z/values). Fixing this requires
   updating `projection.py` to apply the transform pipeline before computing RZ stats.
   This is a future enhancement (doesn't affect current coords_9d correctness).

2. **m_a, m_e, d_n will remain 0** even after SampEn fix: spectral power features have
   near-zero within-run variance after cohort-level normalization. The geometry contract
   correctly zeros these axes. The effective 9D space is 5D + 1D (e_m via SampEn).

3. **Non-pilot subjects still use old sample entropy** (from cached JSONs): Deleting
   all 222 intermediate JSONs and re-running the full pipeline would fix this for all
   subjects, but would take ~6 hours. Will do before final production scaling.
