## Highest-Priority Fixes

### 1. Align docs and H5 schema names
`help/NeuralManifoldDynamics/Output_variables_guide.md` describes:
- `/blocks/block_start_sec`
- `/blocks/block_end_sec`
- `/blocks/block_duration_sec`
- attr `schema_version`

But the actual H5 writes:
- `/blocks/start_sec`
- `/blocks/end_sec`
- `/blocks/duration_sec`
- attr `_schema_version`

This should be made consistent one way or the other. Right now the implementation seems reasonable, but the contract is ambiguous.

### 2. Document the fields that are actually present in `/blocks`
The H5 currently includes useful fields that are not part of the documented contract:
- `derived_from`
- `end_reason`

These are important and should be officially documented, because they materially help provenance and QC.

### 3. Make requested vs realized coordinate contracts explicit
The config in `data/raw/neuralmanifolddynamics_ds006036_20260604_115155/config_ingest_ds006036.yaml` requests both `subject_anchored` and `cohort_anchored` under `mnps_projection.export_contracts`, but the realized root appears effectively subject-anchored for the Jacobian/coords paths that downstream helpers can resolve.

This should be surfaced clearly in `run_manifest.json`:
- requested contracts
- realized contracts
- if a contract was requested but not emitted, why

Right now this is too easy to misunderstand downstream.

### 4. Make block-native stage coverage visible in summaries
In `sub-001`'s `summary.json`, `window_stage_counts` still shows only `-1` windows, even though block inference clearly succeeded and `/blocks` exists. That makes downstream readers think stage logic failed, when in fact block-native logic succeeded.

Recommendation:
- add a dedicated block-native coverage section to per-subject summaries
- separately report:
  - raw stage labels
  - recovered/block-inferred stage intervals
  - block-native windows by stage

## Functional Wishlist

### 5. Add an exact back-reference from `/block_windows` to original analysis windows
This is probably the single most useful downstream improvement.

Please add something like:
- `/block_windows/source_window_index`
- or `/block_windows/original_window_index`

That would let downstream code join block-native windows directly back to:
- `/time`
- `/window_start`
- `/window_end`
- Jacobian center mappings
- MNJ/reachability summaries

Without this, downstream code has to re-match by time bounds or center-time heuristics, which is unnecessary and brittle.

### 6. Add block-native-aware helpers in `ndt-analysis`
Current downstream helpers still assume older state-space paths and older selection logic. In practice this caused failures around:
- legacy reachability resolution
- cohort-like article helpers on the new root

The new block-native design should be a first-class citizen in `ndt-analysis`, especially for:
- state-space resolution across `subject_anchored` and `cohort_anchored`
- selecting windows from `/blocks` and `/block_windows`
- summarizing MNJ/reachability directly on block-native selections

### 7. Add built-in block-native summary exports
It would be very valuable if NMD itself could emit downstream-ready tables such as:
- subject-by-stage metrics
- group contrasts
- MMSE/severity correlations

for block-native selections, rather than forcing every article repo to build its own mapper back onto the original windows.

### 8. Support standard block-native profiles out of the box
The current model becomes much more powerful if block-native windows can be generated by named profiles, for example:
- `whole_block`
- `early_block`
- `mid_block`
- `late_block`
- `last5`
- `tail8`
- `post_offset_0_8`
- `post_offset_8_16`

That would let downstream clinical analyses compare hypotheses cleanly without inventing extra sidecar logic each time.

### 9. Unify `event_locked` and `block_native`
Right now both are useful, but they still feel like parallel systems.

Ideal design:
- `blocks` are the canonical inferred intervals
- `block_windows` are canonical in-block windows
- `event_locked` becomes a derived view over:
  - block start
  - block end
  - post-offset bins
  - other interval-relative references

That would reduce conceptual duplication and improve provenance.

## Provenance and QC Wishlist

### 10. Add `frequency_hz` directly to `/blocks`
Right now downstream code often has to infer frequency from `stage_code`. That is workable, but redundant.

A direct field like:
- `/blocks/frequency_hz`

would make analysis and QC easier.

### 11. Add richer block provenance
Useful optional fields in `/blocks` or a provenance subgroup:
- `source_event_count`
- `bridge_marker_count`
- `carrier_marker_count`
- `start_reason`
- `end_reason` (already present, keep it)
- `inferred_from_profile`
- maybe source event row ids if practical

This would make it much easier to audit borderline blocks.

### 12. Add block-native QC summary files
A dedicated dataset- and subject-level QC export for block-native logic would help a lot:
- number of blocks by stage/frequency
- duration distributions
- gap distributions
- counts of truncated/bridge-tail-ended blocks
- windows per block
- blocks excluded by `min_block_sec` or `min_windows_per_block`

### 13. Clean raw unmapped label handling
Some QC outputs still show strange control-character labels in raw event counts. Even if the raw labels are faithfully preserved, it would help to also emit:
- cleaned label
- normalized label
- mapping status

in a more readable way.

## Design Direction I’d Recommend

The new system looks best if NeuralManifoldDynamics fully embraces an **interval-native** design:

- `blocks` = canonical inferred intervals
- `block_windows` = canonical within-block analysis windows
- `event_locked` = derived interval-relative views
- downstream summaries operate directly on those structures

That is a better long-term architecture than continuing to treat block logic as a patch on top of pre-existing generic epochs.

## Why This Looks Worth Pursuing

The strongest practical reason: when I used the exact block intervals to reselect photic windows, the exploratory exact-block MNJ rerun regained a strong high-frequency AD signal close to the older article pattern. So this is not just cleaner engineering; it appears capable of improving photic targeting in practice.
